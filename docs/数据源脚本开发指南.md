# 数据源脚本开发指南

本文说明如何从零编写、导入和验证一个 Web Video Player 单文件 Provider。示例使用虚构站点 `example.com`，只演示平台契约，不代表任何真实站点。

开始前先阅读：

- [前端展示能力与字段契约](前端展示能力与字段契约.md)
- [前端展示能力与字段契约](前端展示能力与字段契约.md)
- [当前语言无关契约向量](../contracts/current/)
- [当前版本与兼容性](当前版本与兼容性.md)

## 1. 整体流程

```text
分析源站
    -> 编写 manifest
    -> 声明能力与 networkHosts
    -> 实现生命周期和健康检测
    -> 实现页面请求分发
    -> 通过 SourceContext 请求原始响应
    -> 解析源站并映射标准字段
    -> 返回标准响应
    -> 导入、预览和授权
    -> 启用并检查各页面
    -> 验证分页、挑战、失败和升级
```

Provider 是源站业务的唯一负责人。平台不会替脚本拼 URL、带 Cookie、识别验证码、解析 HTML、判断电影电视剧、匹配同一集或修补分页。

## 2. 职责边界

### Provider 必须负责

- 源站 HTTPS 地址、方法、有序请求头、正文和请求顺序。
- Cookie、Token、CSRF、隐藏表单、会话、验证码和失效恢复。
- HTML、JSON、文本、压缩或其它原始响应的解码和解析。
- 源站页面到 `pageKey/moduleKey` 的映射、逻辑分页、筛选和排序。
- 源站字段到 `ContentItem`、筛选响应、健康结果和挑战对象的清洗。
- 详情阶段发现全部线路，为同一内容和同一逻辑剧集生成稳定身份。
- 播放阶段只解析当前 `lineId + episodeId` 的浏览器直连媒体。
- 使用绑定当前 sourceId 的私有存储，并自行管理键和值的语义。

### Provider 不得访问

- 全局 `fetch/XMLHttpRequest/WebSocket`。
- `window/document`、Vue、Router、Store、组件或页面 DOM。
- IndexedDB、localStorage、sessionStorage 或 Repository。
- 项目后端代理地址、其它 Provider 的 Context 或私有空间。
- `eval`、`Function`、静态/动态 import 和外部 npm 依赖。

Provider 只能使用 `initialize(context)` 收到的 SourceContext。公共前端和代理也不能反向解析 Provider 的站点业务。

## 3. 单文件模块

脚本必须是自包含 ES Module，精确导出：

```js
export const sourceManifest = Object.freeze({ /* 静态 JSON 字面量 */ });
export function createProviderFactory() { /* 返回 ProviderFactory */ }
```

禁止 default export、额外命名导出、import、re-export、动态 import 和从 URL 加载代码。`sourceManifest` 必须能够在不执行脚本的情况下由 AST 静态提取，因此字段值不能使用函数、变量、展开语法或计算表达式。

文件、粘贴文本和 HTTPS 地址三种导入方式都执行同一流程：

```text
read -> normalize -> parse -> validate -> trust -> execute -> factory
     -> register -> persist -> optional start -> rollback on failure
```

文本统一按 UTF-8 读取、换行规范化为 LF，并受 1 MiB 上限约束。用户确认的是规范化脚本的 SHA-256；远程内容在确认后发生变化会要求重新确认。

## 4. sourceManifest

完整示例：

```js
export const sourceManifest = Object.freeze({
  schemaVersion: '1.0.0',
  providerApiVersion: '2.0.0',
  id: 'source.com.example',
  name: 'Example Video',
  description: '把 Example Video 的信息页面映射为平台标准对象。',
  authorName: 'Example Author',
  siteUrl: 'https://example.com/',
  version: '1.0.0',
  providerKey: 'source.com.example.provider',
  capabilities: {
    home: true,
    movie: true,
    tv: true,
    search: true,
    detail: true,
    play: true
  },
  settingsSchema: [],
  networkHosts: ['example.com', 'assets.example.com']
});
```

| 字段 | 规则 |
|---|---|
| `schemaVersion` | 当前精确值来自 `contracts/current`，未知字段和未知版本失败关闭。 |
| `providerApiVersion` | 必须与当前 Host ABI 精确一致，不进行 1.x 兼容执行。 |
| `id` | 以 `source.` 开头的小写稳定命名空间；发布后不能随站点页面变化。 |
| `name` | 用户可读纯名称，不拼域名、版本或“数据源”。 |
| `description` | 简述来源和能力，不放敏感信息。 |
| `authorName` | 脚本作者；缺失或空值由平台显示“佚名”。 |
| `siteUrl` | 源站 HTTPS 首页；缺失时不生成外链。 |
| `version` | 脚本业务版本，用于更新和授权失效。 |
| `providerKey` | 固定为 `${id}.provider`。 |
| `capabilities` | 六个页面能力都必须明确布尔值；false 时拒绝对应请求。 |
| `settingsSchema` | 普通非敏感用户设置；不保存 Cookie、Token 或会话。 |
| `networkHosts` | 最小精确 host 列表，不含协议、端口、IP 或通配符。 |

图片和媒体地址可以指向未声明 host，因为浏览器直接加载它们；只有 Provider 通过 SourceContext 发出的信息请求需要进入 `networkHosts`。

## 5. ProviderFactory

Factory 不请求网络、不保存共享 Provider 实例：

```js
export function createProviderFactory() {
  return Object.freeze({
    providerKey: sourceManifest.providerKey,
    supports(definition) {
      return Boolean(
        definition
        && definition.id === sourceManifest.id
        && definition.providerKey === sourceManifest.providerKey
      );
    },
    create({ definition }) {
      if (!this.supports(definition)) throw new Error('Definition 不受支持');
      return createProvider(definition);
    }
  });
}
```

`supports` 必须是无副作用判断并严格返回 boolean。`create` 每次返回独立实例；实例闭包不能跨 sourceId 共享 Context、Cookie、请求序号或缓存。

## 6. 生命周期

Provider 实例公开：

```text
id
initialize(context)
start()
fetchData(request)
fetchFilterMeta(request)
checkHealth()
detectChallenge(response)
continueChallenge(challengeInput)
stop()
dispose()
```

推荐状态机：

```text
created -> initialized -> running -> stopped -> disposed
```

- `initialize` 只接受一次 Context，校验后保存在实例闭包。
- `start` 进入可调用状态；不要把“能启动”当作健康正常。
- 业务方法只在 running 阶段执行，并尊重 `context.signal`。
- `stop` 停止新业务调用并释放短期运行资源，可按 Host 约定幂等。
- `dispose` 永久清除 Context、在途请求、缓存和可变引用，不能恢复实例。
- 生命周期错误应抛出普通 Error 或平台契约允许的稳定错误，不吞掉失败。

Host 负责调用顺序、中止、排空和失败隔离。Provider 不直接修改 SourceManager 状态。

## 7. SourceContext

Context 只包含：

```text
sourceId
network
storage
challenge
logger
signal
```

### 7.1 network

```js
const response = await context.network.request({
  sourceId: sourceManifest.id,
  requestId: `example-${requestSequence}`,
  url: 'https://example.com/discover?page=1',
  method: 'GET',
  headers: [
    { name: 'accept', value: 'text/html' },
    { name: 'referer', value: 'https://example.com/' }
  ],
  body: { encoding: 'none', data: null },
  timeout: 10000,
  maxResponseBytes: 1048576
});
```

请求头是有序数组，同名值不能合并成对象。POST 正文使用：

- `none/null`：无正文。
- `utf8/string`：发送字符串的 UTF-8 字节，JSON 要由 Provider 自己 `JSON.stringify`。
- `base64/string`：发送解码后的原始字节。

响应正文永远是 `ArrayBuffer`。HTTP 4xx/5xx 仍是成功运输响应，由 Provider 结合状态、头和正文判断业务失败。代理不会替脚本解码 JSON、HTML 或字符集。

媒体流不经过这个代理；`maxResponseBytes` 应只覆盖信息页面和接口响应。

### 7.2 storage

`storage` 提供绑定当前 sourceId 的五个分区：

```text
settings / credentials / session / cache / diagnostics
```

每个分区只提供 `get/set/remove/list/clear`。普通设置放 settings，敏感凭据放 credentials，会话放 session，可丢弃内容放 cache，受控诊断放 diagnostics。键、值、版本和清理语义由 Provider 自己负责；不要复制用户收藏和播放历史。

### 7.3 challenge

Provider 检测到登录、验证码或其它用户交互后，构造标准 SourceChallenge 并调用 `context.challenge.request(challenge)`。页面只显示平台挑战界面，Provider Promise 保持等待；用户提交后由 `continueChallenge` 更新私有会话并继续。

挑战对象不能携带原始 Cookie、Token、整页 HTML 或脚本。取消、超时和不支持必须明确失败，不能返回旧内容。

### 7.4 logger 与 signal

logger 只记录稳定事件、阶段和安全摘要。禁止记录请求头值、Cookie、Token、完整 URL 查询、正文、媒体地址、用户数据或堆栈。

每次网络和长解析前后检查 `signal.aborted`。中止后停止后续请求和状态写入，不自行固定等待或轮询。

## 8. 解码和解析

Provider 根据响应头、BOM、站点事实或受审回退顺序选择字符集。推荐分层：

```text
requestEndpoint
    -> decodeResponseBytes
    -> detectBusinessFailureOrChallenge
    -> parseHtmlOrJson
    -> normalizeSourceFields
    -> buildStandardResponse
```

- JSON：先把 ArrayBuffer 解码为文本，再 `JSON.parse`；非法 JSON 抛错。
- HTML：使用脚本内自包含的受审解析方法，不把选择器交给公共前端。
- 文本：保留站点需要的换行与分隔语义。
- 二进制/压缩：只有站点确实需要且脚本能安全处理时解析；不能要求代理业务解码。
- Cookie：从有序响应头中处理多个 `set-cookie`，保存到 Provider 私有 session/credentials。

解析失败不能返回空成功对象覆盖页面旧事务，也不能将登录页、验证码页或错误页当作内容列表。

## 9. 页面请求分发

`fetchData` 应先严格校验 `request.sourceId` 和 capability，再按标准键分发：

```js
async function fetchData(request) {
  assertRunning();
  assertRequestSource(request);

  if (request.pageKey === 'home') {
    if (request.moduleKey === 'banners') return fetchHomeBanners(request);
    if (request.moduleKey === 'hotMovies') return fetchHomeHotMovies(request);
    if (request.moduleKey === 'hotTv') return fetchHomeHotTv(request);
    if (request.moduleKey === 'movieRanking') return fetchMovieRanking(request);
    if (request.moduleKey === 'tvRanking') return fetchTvRanking(request);
    throw new Error('未知首页区域');
  }

  if (request.pageKey === 'movie') return fetchMoviePage(request);
  if (request.pageKey === 'tv') return fetchTvPage(request);
  if (request.pageKey === 'search') return fetchSearchPage(request);
  if (request.pageKey === 'detail') return fetchDetail(request);
  if (request.pageKey === 'player') return fetchPlayer(request);
  throw new Error('不支持的页面请求');
}
```

这里的分支是公共页面契约，不是源站特判。源站分类、标签、路由和选择器只能出现在本 Provider 内部。

## 10. 列表、分页、筛选和排序

### 首页

Provider 可以从同一源站页面拆出五个标准区域，也可以从不同信息端点组合。`moduleKey` 必须与请求一致，不能返回其它板块冒充。

### 电影与电视剧

电影每页默认 12，电视剧默认 18。源站若把多个固定栏目合并展示，Provider 自己建立确定性逻辑页：按栏目顺序取对应窗口，合并后返回标准分页。

### 搜索

只接受非空 keyword。Provider 必须解析源站真实搜索容器和 pagination，并用源站类型字段与可靠辅助信息确定 `movie/tv`。搜索进入详情时应按完整标题和内容身份排除相似作品。

### 筛选

`fetchFilterMeta` 返回标准 groups。源站参数值可以不透明，但平台 value 必须稳定并能由 Provider 反向构造请求。分类、类型、年份、地区、状态和排序按源站真实能力提供；无能力时返回空组。

不要通过固定数组长度伪造总页数，不要把“下一页存在”仅等同于当前页满额，也不要在页面代码中保存源站 URL。

## 11. ContentItem 映射

所有列表至少返回 `id/sourceId/type/title`。应尽量保留卡片明确提供的：

```text
poster / cover / description
year / area / language / genres / tags / displayTags
score / quality / badge / rank
movie.duration
tv.totalEpisodes / latestEpisode / updateStatus / season
```

详情再补齐别名、完整简介、导演、编剧、演员、日期、状态、剧照和播放目录。未知数字使用 null，未知字符串使用空字符串，未知数组使用空数组；不能写“未知”占位，也不能把原始 HTML 放进标准字段。

`source.rawData` 可以在开发时保留安全、有限的原始结构，但页面不消费它，正式脚本不应存储大段响应或敏感值。

## 12. 详情、多线路和逻辑剧集

详情请求必须返回当前内容全部已发现线路：

- `line.id`：内容内稳定、不透明，不使用数组索引或媒体 URL。
- `line.name`：用户可读线路名称。
- `line.available`：Provider 已知的业务可用声明；临时网络探测由平台另行显示。
- `episode.id`：同一 ContentItem 内的逻辑剧集身份。
- `episode.label`：当前线路按钮文案，如“第1集”“HD”“正片”。
- `episode.playable`：当前目录是否允许发起播放请求。

跨线路同一集只有在季集号、明确集号或完整特辑语义足够时使用相同 episode.id。不确定时宁可使用不同身份，让平台提示手动选集，不能按数组位置或相似标题强配。

电影通常使用 `kind='feature'` 和稳定 id `feature`。电视剧使用 `kind='episode'`，特辑使用 `kind='special'`。线路缺集时只返回真实存在分集，不用相邻集补齐。

## 13. 播放与媒体探测

player 请求根据 `contentId + playbackSourceId + episodeId` 定位一个目标。Provider 可以复用详情缓存，但必须重新确认目标属于当前内容和线路。

正式播放返回：

```js
playback: {
  lineId: 'line-main',
  episodeId: 'season-1:episode-1',
  media: {
    type: 'hls',
    url: 'https://media.example.com/episode-1.m3u8',
    quality: '1080P',
    deliveryMode: 'direct'
  }
}
```

`requestPurpose='probe'` 使用相同 Provider 解析能力验证候选，但不创建播放器会话。探测应选择真实代表分集，不并发轰炸源站；平台协调器负责串行、取消和探测顺序，Provider 负责请求必要地址和判断业务可达。

媒体 URL 必须为浏览器可直连 MP4/HLS，不能携带凭据、请求头或项目代理路径。无法解析时抛错，不返回空 playback。

## 14. 健康检测

`checkHealth()` 应请求 Provider 自己选择的代表性轻量目标，并确认响应能够解析成预期业务内容。仅收到 HTTP 2xx、Host 启动成功或 DNS 可达不能判定正常。

```js
return {
  healthStatus: 'normal',
  checkedAt: new Date().toISOString(),
  unavailableReason: ''
};
```

失败返回 `healthStatus='unavailable'` 和非空安全原因。`checking` 由平台在调用期间维护，Provider 不能返回。检测与页面请求相互独立：页面失败可以触发同源复检，但不能直接篡改健康状态。

## 15. 最小完整骨架

```js
export const sourceManifest = Object.freeze({
  schemaVersion: '1.0.0',
  providerApiVersion: '2.0.0',
  id: 'source.com.example',
  name: 'Example Video',
  description: '虚构示例数据源。',
  authorName: 'Example Author',
  siteUrl: 'https://example.com/',
  version: '1.0.0',
  providerKey: 'source.com.example.provider',
  capabilities: { home: true, movie: true, tv: true, search: true, detail: true, play: true },
  settingsSchema: [],
  networkHosts: ['example.com']
});

function createProvider(definition) {
  let context = null;
  let phase = 'created';

  function assertRunning() {
    if (phase !== 'running' || !context) throw new Error('Provider 未运行');
  }

  async function fetchData(request) {
    assertRunning();
    if (request.sourceId !== definition.id) throw new Error('sourceId 不匹配');
    // 按第 9 节分发，并返回标准 SourceDataResponse。
    throw new Error(`尚未实现页面: ${request.pageKey}`);
  }

  async function fetchFilterMeta(request) {
    assertRunning();
    return { sourceId: definition.id, pageKey: request.pageKey, request, groups: [], updatedAt: new Date().toISOString() };
  }

  async function checkHealth() {
    assertRunning();
    return { healthStatus: 'unavailable', checkedAt: new Date().toISOString(), unavailableReason: '尚未实现健康检测。' };
  }

  return Object.freeze({
    id: definition.id,
    async initialize(nextContext) { if (phase !== 'created') throw new Error('重复初始化'); context = nextContext; phase = 'initialized'; },
    async start() { if (phase !== 'initialized' && phase !== 'stopped') throw new Error('启动顺序无效'); phase = 'running'; },
    fetchData,
    fetchFilterMeta,
    checkHealth,
    async detectChallenge() { return null; },
    async continueChallenge() { throw new Error('当前 Provider 不支持挑战继续'); },
    async stop() { if (phase === 'running') phase = 'stopped'; },
    async dispose() { context = null; phase = 'disposed'; }
  });
}

export function createProviderFactory() {
  return Object.freeze({
    providerKey: sourceManifest.providerKey,
    supports(definition) {
      return Boolean(definition && definition.id === sourceManifest.id && definition.providerKey === sourceManifest.providerKey);
    },
    create({ definition }) {
      if (!definition || definition.id !== sourceManifest.id || definition.providerKey !== sourceManifest.providerKey) {
        throw new Error('Definition 不受支持');
      }
      return createProvider(definition);
    }
  });
}
```

骨架故意让未实现页面和健康检测失败关闭。开发者应逐项替换为真实源站实现，不能用空列表、固定正常或 mock 数据伪装完成。

## 16. 导入、恢复、更新和卸载

1. 设置 → 数据源管理 → 导入数据源。
2. 选择文件、粘贴文本或 HTTPS 地址。
3. 平台静态预检 manifest、导出、禁用语法、容量和 SHA-256，不执行脚本。
4. 用户核对名称、版本、作者、站点、能力、host 和执行风险。
5. 确认后平台重新读取并核对哈希，再执行、验证 Factory、注册和原子保存。
6. 用户选择启用时，Host 初始化并启动；失败按副作用逆序回滚。

刷新浏览器后，平台只从 Repository 保存的同一 `scriptContent` 恢复，不重新读取文件或远程 URL。更新脚本内容或版本会使旧授权失效，需要重新确认；卸载自定义源会释放 Host、删除保存图和注销工厂，但用户收藏与历史按平台兼容规则保留。

## 17. 错误与安全

加载阶段稳定错误对象只包含 `code/stage/message/field`。脚本运行错误应给出安全、可定位的阶段说明，禁止泄漏：

```text
脚本文本、Cookie、Token、Authorization、请求头值
完整 URL 路径和查询、请求/响应正文、媒体地址
用户收藏历史、Provider 私有存储、cause 和堆栈
```

不要自动重试所有失败。只有 Provider 明确知道会话刷新或挑战完成后请求可恢复时，才在脚本内部执行有限、可取消的重试；不能轮询、固定等待或吞掉最终失败。

## 18. 验收清单

### 静态契约

- 只有两个允许导出，无 import、动态 import、默认导出或越权全局。
- manifest 字段精确，id/providerKey/version/capabilities/networkHosts 合法。
- 当前合法和非法 manifest 行为符合 `contracts/current`。
- 生命周期、SourceContext、错误和日志不越界。

### 页面

- 首页五个区域都有正确 pageKey/moduleKey、类型、顺序和上限。
- 电影 12、电视剧 18、搜索 12 的分页稳定，筛选值可往返。
- 搜索类型、详情标题和内容 id 不误匹配。
- 卡片保留源站可确定的全部标准元信息。
- 详情提供完整多线路 playCatalog，电影和电视剧标签正确。
- 播放只返回目标媒体，跨线路同集和缺集行为正确。

### 失败路径

- 非 2xx、非法正文、挑战、超时、超限、中止和解析失败明确关闭。
- 健康检测验证业务内容，不把 HTTP 成功当正常。
- dispose 后无 Context、在途请求和缓存泄漏。
- 刷新后从保存脚本恢复，更新和卸载不破坏用户收藏历史。

### 发布前

- 在设置页核对脚本名称、作者、源站名称/域名、版本和 capability。
- 核对 networkHosts 是最小集合，日志不含敏感数据。
- 运行 `npm run build`，并按受影响页面完成真实数据、失败路径和浏览器验收。
- 内置 Provider 还必须执行内置 Provider 发布规范；普通自定义源不能直接进入 `datasource/`。
