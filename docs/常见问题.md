# 常见问题

## 项目怎么启动？

安装前后端依赖后，在根目录执行 `npm run dev`。默认读取 `config/project.config.js` 并启动全部服务。详见 [快速开始](快速开始.md)。

## 为什么前端能打开但所有数据请求失败？

通常是后端未启动、`runtime.backendOrigin` 不正确或浏览器 Origin 未进入后端 `allowedOrigins`。项目不会在代理失败时回退模拟数据。

## 为什么浏览器提示 CORS？

核对地址栏的“协议 + 主机 + 端口”是否精确存在于 `config/backend.config.js` 的 `server.allowedOrigins`。不要使用 `*`，也不要把完整页面路径写进 Origin。

## 0.0.0.0 是访问地址吗？

不是。它表示后端监听本机全部 IPv4 接口，浏览器仍通过 `localhost`、服务器域名或反向代理域名访问。

## 为什么生产前端修改配置后没有生效？

`client/dist/config/frontend.config.js` 的 `runtime.backendOrigin` 可以修改后刷新生效。`build.basePath` 已参与资源路径生成，必须修改源码配置后重新构建。

## 为什么刷新详情或播放深层地址显示 404？

静态服务器需要 history 路由回退到 `index.html`。GitHub Pages 应发布准备脚本生成的 `404.html`；其它服务器配置等价 fallback。

## 为什么数据源状态显示不可用？

Provider 健康检测需要请求其自选代表目标并解析出业务内容。HTTP 2xx 不是唯一标准。检查后端、网络、源站挑战、Provider networkHosts 和设置页安全原因；临时页面错误与数据源健康状态是两类状态。

## 为什么详情有线路，但播放失败？

详情目录用于罗列和线路级代表探测，正式播放还要解析当前线路和分集的直连媒体。媒体失效、需要自定义头、源站限制浏览器或网络不可达都会失败。播放页仍应显示线路与选集供改选。

## 为什么线路显示可用，某一集却不可用？

线路代表分集可达不表示每一集都可达。播放页会优先检测当前线路当前集，再后台检查其它分集和线路。状态是当前会话探测事实，不写回永久 ContentItem。

## 为什么切换线路没有自动切到同一集？

只有 Provider 为跨线路同一集提供相同逻辑 episode.id 时才能自动匹配。新线路缺集或身份证据不足时，平台只切换选集列表并提示手动选择，不会用相邻集或数组位置猜测。

## 历史记录中的数据源被删除怎么办？

收藏和历史快照仍会保留。点击失效记录后，平台引导使用可用数据源搜索；用户确认新内容和分集后迁移恢复关系，并从该集已有历史进度继续。

## 更新后需要清理 IndexedDB 吗？

不需要。项目维护连续原子迁移链，失败会保留旧数据。若出现 blocked，关闭其它同源标签页后重试；不要把清库当成升级步骤。

## 为什么导入 Provider 被拒绝？

常见原因包括：脚本超过容量、不是 UTF-8、存在 import/额外导出、manifest 字段或版本不匹配、providerKey 与 id 不一致、networkHosts 使用通配符，或确认后的远程文本 SHA-256 已变化。

## 验证码怎么处理？

Provider 检测挑战后通过 SourceContext challenge 请求平台交互。验证码、登录和会话属于 Provider；页面和后端不会按站点编写验证码分支。

## Render 上的日志文件会一直保留吗？

不一定。stdout/stderr 由平台收集；实例临时文件系统中的 JSONL 会随重建丢失。需要持久文件日志时使用持久磁盘并修改日志目录，同时保留轮转上限。

## 为什么媒体不走后端代理？

后端只搬运容量受控的信息请求。媒体体积大、持续时间长，并涉及浏览器媒体栈和来源策略，因此 `playback.media.url` 由浏览器直连。

## 如何报告问题？

通过项目 GitHub Issues 提供提交哈希、环境、稳定错误码和脱敏复现步骤。不要公开 Cookie、Token、Authorization、完整 URL 查询、原始响应、媒体地址、播放历史或个人信息。
