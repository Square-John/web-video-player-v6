# Contributing

感谢你参与 Web Video Player。项目欢迎缺陷修复、通用平台能力、文档改进和符合当前 ABI 的 Provider；所有贡献都必须保持多数据源平台边界和用户数据升级兼容。

## 开始之前

1. 先在 GitHub Issues 搜索相同问题。
2. 大型功能、公共契约或持久化变化先创建讨论问题，说明目标、用户影响和兼容方案。
3. 安全漏洞不要公开披露，按 [安全策略](SECURITY.md) 报告。
4. Provider 必须有权公开脚本和署名信息，不要提交凭据、账号、Cookie、Token 或受限制内容。

## 本地开发

```bash
npm --prefix client install
npm --prefix server install
npm run dev
```

配置、分端启动和生产构建见 [快速开始](快速开始.md)。提交前至少运行：

```bash
npm run build
```

如果改动只涉及某个 package，可以先运行该 package 的定向检查；最终仍以受影响范围要求的完整构建为准。

## 贡献边界

- Provider 独占源站请求、会话、挑战、解析和字段映射。
- 页面、Store、通用 Service、Runtime、Source Shell 和后端代理不能增加站点 id、域名、选择器或 Cookie 分支。
- 后端只做无状态、安全、无损的信息请求运输，不代理媒体、不解析业务。
- 字段、方法、错误和数据流变化必须同步当前契约、公开说明、实现与验证。
- IndexedDB、设置、收藏、历史、快照和 Provider 私有存储变化必须提供连续无损迁移，不能要求用户清库。
- 不用固定等待、轮询、静默降级、双写、兼容别名、魔法数字或放宽契约掩盖问题。

## Provider 贡献

先阅读：

- [数据源脚本开发指南](数据源脚本开发指南.md)
- [前端展示能力与字段契约](前端展示能力与字段契约.md)
- [当前契约向量](../contracts/current/)

系统 Provider 需要完整作者、站点名称、HTTPS 地址、版本、能力和最小 networkHosts。新增 Provider 应只增加脚本及其发布事实；如果需要修改公共前端才能识别站点，说明脚本尚未满足可插拔契约。

## 提交内容

一个变更应包含完整能力闭环：

- 根因和职责归属清楚的实现。
- 与代码同步的维护注释。
- 对应契约、公开文档和失败路径。
- 与风险匹配的验证和生产构建结果。
- 持久化变化的旧版本升级样本。
- 不包含构建产物、日志、缓存、凭据、个人路径和无关格式化。

提交信息使用简短动词说明结果，例如 `fix: preserve playback history during source recovery`。Pull Request 描述应列出行为变化、兼容影响、验证结果和未执行项目。

## 文档

根 README 保持简洁，详细使用说明进入 `docs/`。字段和协议说明必须与当前实现及 `contracts/current/` 一致；发现不一致时先修正实现和契约，再更新说明。

## 行为准则

请围绕事实、代码和用户影响讨论，尊重维护者、贡献者、站点权利人和使用者。骚扰、歧视、泄漏隐私或利用项目传播无权内容的贡献不会被接受。
