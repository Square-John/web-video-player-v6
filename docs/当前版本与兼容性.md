## 1. 运行要求

- Node.js 20 或更高版本。
- npm 与当前 lockfile 对应的确定安装。
- 支持 ES Modules、IndexedDB、AbortController、Blob URL 和现代 JavaScript 的浏览器。
- MP4 依赖浏览器原生能力；HLS 由项目播放器适配层处理，但最终媒体仍需浏览器可访问。
- 公网前端和后端使用 HTTPS。

不支持需要 Internet Explorer、旧版 WebView 或禁用 IndexedDB/ES Modules 的环境。

## 2. 版本边界

项目分别维护：

- 项目发布版本。
- Provider 脚本业务版本。
- Provider ABI。
- sourceManifest schema。
- Proxy Protocol。
- 内置 Provider 目录 revision/version。
- IndexedDB schema。

这些版本不能互相替代。当前精确协议与合法/非法向量见 [contracts/current](../contracts/current/)；旧版本由 Git 提交和发布标签追溯，不作为当前兼容输入。

## 3. Provider 兼容

Host 只执行与当前 Provider ABI 精确匹配的脚本。旧 ABI 自定义包可以保留在 Repository 中供用户识别和处理，但不能通过兼容别名或隐式转换运行。

Provider 自身 `version` 用于更新比较和授权失效，不决定 ABI。脚本文本或版本变化后需要用户重新确认授权。刷新恢复始终执行已保存的同一脚本文本，不重新下载远程地址。

## 4. 浏览器数据升级

项目从兼容基线开始维护连续 IndexedDB 迁移链。升级遵循：

- 不修改数据库名逃避迁移。
- 不清库、不要求用户手工删除浏览器数据。
- 收藏、历史、播放进度和设置优先保留。
- 内置 Provider 更新只替换系统包/定义/授权事实，不删除无关用户内容。
- 迁移在单事务失败时回滚，保留旧版本数据。
- 同 schema 启动仍核对内置目录发布身份，内容相同则不产生写入。

浏览器提示数据库被其它标签页阻塞时，关闭同源旧页面后重试；这不是要求清除数据。

## 5. 配置兼容

三份根配置使用共同 schemaVersion。后端在监听前拒绝缺失新增安全或日志字段的旧配置；前端运行配置由外部脚本先于应用读取。

配置升级必须同步根配置、校验器、调用者和部署指南，不提供环境变量或命令行的静默旧字段回退。

## 6. 协议升级流程

发布新的不兼容公共协议时：

1. 在发布提交或标签中冻结现有 `contracts/current/` 文件和 SHA-256。
2. 原子替换唯一 `contracts/current/`。
3. 同步前后端调用者、协议版本和公开指南。
4. 不在公开源码树保留历史目录、旧路径转发、副本或当前实现兼容读取。

## 7. 获取帮助

升级或兼容问题先查看 [常见问题](常见问题.md)。报告问题时提供项目提交、浏览器/Node 版本、稳定错误码和脱敏后的复现步骤，不附带凭据、完整源站响应或用户数据。
